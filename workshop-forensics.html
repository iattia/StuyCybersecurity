Challenge 1: The Disguised File 🎭

You've found a suspicious file named "document.txt", but something doesn't seem right. The file signature suggests it's not actually a text file.

File Properties:

Filename: document.txt

Size: 1,247,892 bytes

Modified: 2025-10-25 14:30:22

Hex Dump (First 32 bytes):

00000000: 89 50 4e 47 0d 0a 1a 0a 00 00 00 0d 49 48 44 52

00000010: 00 00 04 00 00 00 03 20 08 02 00 00 00 8f 61 cc

File Signature Analysis

File signatures (magic numbers) are the first few bytes that identify file types:

Common Signatures:

PNG: 89 50 4E 47 0D 0A 1A 0A

JPEG: FF D8 FF

PDF: 25 50 44 46

ZIP: 50 4B 03 04

Analysis Tools:

file command (Linux/Mac)

hexdump -C filename

xxd filename | head

Online hex editors

Hint: Look at the hex dump. The bytes "89 50 4E 47 0D 0A 1A 0A" are the PNG file signature. This "text file" is actually a PNG image!

Challenge 3: The Invisible Message 🔍

This photograph looks normal, but data might be hidden in the least significant bits (LSB) of the pixel values. Use LSB analysis to extract the hidden message.

Sample image for LSB analysis (400x300px)

LSB Steganography Basics:

  • Modifies least significant bit of pixels
  • Nearly invisible to human eye
  • Can hide text, files, or other images
  • Common in PNG and BMP formats

Detection Tools:

# zsteg for PNG/BMP analysis

zsteg image.png

# StegSolve (GUI tool)

java -jar stegsolve.jar

# Python PIL analysis

python lsb_extract.py image.png

$ zsteg suspicious_photo.png

b1,r,lsb,xy .. text: "This is not the flag you're looking for"

b1,g,lsb,xy .. text: "Keep searching, young padawan"

b1,b,lsb,xy .. text: "flag{l5b_st3g4n0gr4phy_n1nj4}"

b2,r,lsb,xy .. random data

b2,g,lsb,xy .. random data

Channel Analysis Explanation:

b1,r,lsb,xy: LSB of red channel - contains decoy text

b1,g,lsb,xy: LSB of green channel - contains decoy text

b1,b,lsb,xy: LSB of blue channel - contains the real flag!

Note: Attackers often use different channels to confuse analysis

Hint: The zsteg output shows different messages in different color channels. The flag is hidden in the blue channel's LSB: flag{l5b_st3g4n0gr4phy_n1nj4}

Spectrogram Analysis:

Challenge 5: The Digital Onion 🧅

The final challenge! This file appears to be a simple document, but multiple steganographic techniques have been layered together. Peel back each layer to find the ultimate prize.

File: final_evidence.pdf

Surface level: Appears to be a financial report (23 pages)

Size: 4.2 MB (unusually large for a text document)

Creation date: Modified multiple times in the last week

Layer 1: Metadata Analysis

$ exiftool final_evidence.pdf

Creator: Adobe InDesign CS6

Title: Q3 Financial Report

Keywords: ZmxhZ3toaWRkM25faW5fbTN0NGQwdDR9

Author: John Smith

Layer 2: Base64 Decoding

Decode the keywords field from Base64:

$ echo "ZmxhZ3toaWRkM25faW5fbTN0NGQwdDR9" | base64 -d

flag{hidd3n_in_m3t4d0t4}

Layer 3: Hidden Files Detection

$ binwalk final_evidence.pdf

0 0x0 PDF document, version 1.4

892845 0xDA12D PNG image, 1x1, 8-bit colormap

893156 0xDA464 Zip archive, encrypted

Layer 4: Password Discovery

The 1x1 PNG contains LSB data revealing the ZIP password:

$ zsteg tiny_image.png

b1,b,lsb,xy .. text: "password: EVIDENCE2025"

Final Layer: After extracting and decrypting the ZIP file with password "EVIDENCE2025", you find a text file containing the master flag that proves successful completion of all forensic challenges.

Hint: This challenge combines multiple techniques: metadata analysis reveals a Base64 flag, binwalk finds hidden files, LSB steganography reveals a password, leading to the final flag: flag{m4st3r_f0r3ns1cs_1nv3st1g4t0r}

Investigation Methodology

  1. Initial Assessment: File type, size, timestamps
  2. Metadata Extraction: Hidden information in headers
  3. Signature Analysis: Verify file types and detect anomalies
  4. Content Carving: Extract embedded files and data
  5. Steganographic Analysis: Search for hidden messages
  6. Correlation: Link findings across multiple files
  7. Documentation: Maintain chain of custody

🌐 Mission Overview

Your Objective

You've discovered a suspicious web application that appears to have weak security controls. Your mission is to escalate from a guest user to admin access by exploiting client-side vulnerabilities and parameter tampering techniques.

Attack Vector

  1. Reconnaissance - Find hidden credentials
  2. Initial Access - Login as low-privilege user
  3. Parameter Tampering - Escalate privileges
  4. Admin Access - Access restricted resources

Common Web Vulnerabilities

Client-Side Storage:

Cookies, localStorage, JavaScript source

Parameter Tampering:

URL parameters, POST data, headers

Access Controls:

Weak authorization checks

Information Disclosure:

Comments, debug info, error messages

Challenge 2: The Sweet Cookie Jar 🍪

After logging in, the application sets several cookies. One contains sensitive information that could help with privilege escalation.

Current Cookies (inspect with F12 → Application/Storage):

session_id: 7f3e8b4c2a9d1e5f

user_role: guest

preferences: {"theme":"dark","lang":"en"}

debug_info: user=testuser&role=guest&admin_override=flag{c0ok13_m0nst3r_4pp30v3d}

Cookie Analysis

  • session_id: Standard session identifier
  • user_role: Client-side role storage (dangerous!)
  • preferences: JSON configuration data
  • debug_info: Looks suspicious...

Real-World Impact

  • Client-side role checks are easily bypassed
  • Debug information can leak sensitive data
  • Cookies can be modified by users
  • Always validate on server-side
Hint: Look at the debug_info cookie. It contains URL-encoded data with what appears to be a flag value for admin_override.

Parameter Tampering Techniques:

1. Change user parameter: Try common usernames like 'admin', 'administrator', 'root'

2. Modify role parameter: Change 'guest' to 'admin', 'administrator', or 'superuser'

3. Add new parameters: Try adding '&admin=true' or '&debug=1'

4. Remove restrictions: Try '&bypass=true' or '&elevated=1'

Challenge 4: The X-Factor Headers 📡

Some applications check custom HTTP headers for authorization. This application checks for a specific header to grant admin access.

Current Request Headers:

Host: vulnerable-corp.com

User-Agent: Mozilla/5.0...

Accept: text/html,application/xhtml+xml

Cookie: session_id=7f3e8b4c2a9d1e5f; user_role=guest

X-Admin-Token: missing

Common Admin Headers

  • X-Admin: true
  • X-Forwarded-For: 127.0.0.1
  • X-Real-IP: localhost
  • X-Admin-Token: [token]
  • Authorization: Bearer [token]

Tools to Test Headers

  • Browser DevTools: Network tab → Edit and resend
  • Burp Suite: Intercept and modify requests
  • cURL: curl -H "X-Admin: true"
  • Browser Extensions: ModHeader, Header Editor

Scenario: The application expects X-Admin-Token: SUPERSECRET123 to grant admin access. This token was hardcoded and found in a previous code review.

Hint: The admin token is "SUPERSECRET123". When this header is properly set, you would receive the flag: flag{h34d3r_h4ck1ng_3l1t3}

🛡️ Defense & Best Practices

Secure Development

  • Server-Side Validation: Never trust client input
  • Proper Authentication: Use secure session management
  • Authorization Checks: Verify permissions on every request
  • Input Sanitization: Validate all parameters
  • Security Headers: Use HSTS, CSP, etc.

Code Review Checklist

  • Remove debug/test credentials
  • No sensitive data in client-side code
  • Validate user roles server-side
  • Use HTTPS for all sensitive operations

Penetration Testing

  • Reconnaissance: Gather information about the target
  • Vulnerability Scanning: Use automated tools
  • Manual Testing: Parameter tampering, injection
  • Privilege Escalation: Attempt to gain higher access
  • Documentation: Record findings and impact

Useful Tools

  • Burp Suite: Web application testing
  • OWASP ZAP: Free security scanner
  • Browser DevTools: Built-in debugging
  • Postman/Insomnia: API testing

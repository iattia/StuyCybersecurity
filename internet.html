Foundations

How the internet works

The internet is a network of networks. Security makes more sense once you know what is moving, which devices make decisions, and where the system expects trust.

Start with one ordinary action

You type a website address into a browser. The browser needs to find the server, establish a connection, protect the connection if HTTPS is used, send an HTTP request, receive a response, and load additional files. Each step depends on a different protocol and can fail or be attacked in a different way.

A protocol is an agreement about message format and behavior. Protocols let equipment and software made by different organizations communicate. They also create assumptions. Security work often begins by asking whether those assumptions still hold when a participant is dishonest, compromised, or simply mistaken.

Layers are a way to divide the problem

LinkMove frames across one local connection.Ethernet, Wi-Fi, ARPWho is on the local network? Can frames or addresses be spoofed?

The layers are not physical boxes and real systems do not always fit perfectly. They are a useful way to decide which part of the communication you are examining.

Local networks

Your laptop normally reaches a nearby switch or wireless access point. On an Ethernet-like network, interfaces have link-layer addresses. ARP helps an IPv4 host learn which local hardware address corresponds to a nearby IP address. A device called a router connects this local network to other networks.

Most home networks use private IP addresses internally and network address translation at the router. NAT changes address and port information as connections cross the boundary. It is not a complete firewall or identity system, although its state can limit unsolicited inbound connections.

DHCP

The Dynamic Host Configuration Protocol commonly supplies a device with an IP address, network prefix, default gateway, DNS servers, and lease time. If this configuration is wrong or malicious, traffic can be sent to the wrong place.

Wireless networks

Wi-Fi adds radio communication, association, and wireless encryption. A password protects access to the network, while modern enterprise networks may authenticate individual users or devices. The security of the application still matters even when Wi-Fi encryption is strong.

IP addresses and routing

An IP address identifies an interface within an addressing system. A network prefix groups addresses. A host compares the destination with its local routes; if the destination is not local, the packet usually goes to a default gateway.

Routers examine destination addresses and select next hops. Across the public internet, independent networks exchange reachability information using the Border Gateway Protocol. Routing answers where traffic should go. It does not automatically guarantee that the destination is honest or that the path is private.

Useful distinction

An IP address identifies where traffic is delivered at the network layer. A domain name is a human-manageable name. A port identifies a transport endpoint. A URL describes an application resource. They are related but not interchangeable.

DNS: names to records

DNS is a distributed database. A resolver asks authoritative name servers for records and caches answers for a limited time. Common records include A for IPv4, AAAA for IPv6, CNAME for aliases, MX for mail routing, and TXT for text used by many verification systems.

DNS security questions include who controls a domain, whether an answer was forged, whether a resolver or cache was poisoned, and whether sensitive names are exposed. DNSSEC can authenticate signed DNS data, while encrypted DNS transports protect queries on part of their path. Neither one proves that the website itself is safe.

dig example.com A
dig example.com AAAA
dig example.com MX
dig example.com TXT

TCP, UDP, and QUIC

TCP creates an ordered byte stream. It establishes state, numbers bytes, acknowledges received data, retransmits missing segments, and controls sending speed. Applications still need their own message boundaries because TCP delivers bytes rather than application records.

UDP sends datagrams without TCP's delivery and ordering behavior. It is useful when an application wants low overhead or implements its own reliability. QUIC runs over UDP and provides secure, multiplexed connections; HTTP/3 uses it. Choosing UDP does not mean choosing insecurity, and choosing TCP does not make application messages trustworthy.

HTTP and the web

The web is one application built on the internet. A browser sends an HTTP method, path, headers, and sometimes a body. The server returns a status, headers, and body. HTML describes document structure, CSS controls presentation, and JavaScript runs application logic in the browser.

Cookies let a browser store values associated with a site. A session cookie often points to server-side login state. Since a browser user can inspect and change client-side data, permissions must be enforced by the server.

GET /account HTTP/1.1
Host: example.com
Cookie: session=opaque-value
Accept: text/html

TLS and HTTPS

TLS protects data in transit and lets a client authenticate a server through certificates and trusted certificate authorities. The client and server agree on cryptographic parameters, establish keys, and then protect application records.

HTTPS means HTTP over TLS. It helps prevent someone on the path from reading or silently altering requests. It does not guarantee that a site is honest, free of vulnerabilities, or authorized to access a particular record.

Cloud services are still computers and networks

Cloud providers offer virtual machines, containers, databases, storage, identity systems, queues, and serverless functions through managed interfaces. The physical infrastructure is abstracted, but the same questions remain: who can access a resource, which network paths exist, where secrets are stored, how data is backed up, and who is responsible for updates.

A content delivery network places caches or proxy servers near users. A load balancer distributes traffic among servers. These layers improve performance and availability but can create security problems if they parse requests or cache responses differently from the application.

Where cybersecurity fits

  • Endpoint security protects devices that create and consume traffic.
  • Network security controls and observes connections between systems.
  • Application security makes requests, parsers, sessions, and business rules safer.
  • Identity security controls accounts, credentials, roles, and service access.
  • Cryptography protects data and authenticates participants when used correctly.
  • Monitoring and response help an organization notice and recover when preventive controls fail.

Open your browser's network panel and load a simple page. Identify the DNS name, remote address, protocol, request method, response status, content type, cookies, and the additional files loaded by the page. Explain which details belong to DNS, transport, TLS, and HTTP.
